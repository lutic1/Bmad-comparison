# Decision Log — Percentage Discount Codes at Checkout

## Session: 2026-05-19

---

### DL-1 — Checkout = POST /orders (no separate endpoint)
**Decision:** Discount code is applied at `POST /orders`; no separate `/checkout` or `/apply-discount` endpoint created.
**Reason:** The service has no separate checkout step; order creation IS checkout. Adding a new endpoint would duplicate logic and contradict the CLAUDE.md guidance against unnecessary abstractions.
**Status:** Recorded — confirm with architect.

---

### DL-2 — Monetary storage: discounted total stored in Order.total
**Decision:** `Order.total` stores the post-discount amount (consistent with existing pattern). `original_total` is stored as a separate column (not computed).
**Reason:** The existing `total` field is what callers already read; changing its meaning would break consumers. Storing `original_total` persisted avoids recomputation and provides an audit trail.
**Status:** [ASSUMPTION] — OQ-2 open; architect to confirm.

---

### DL-3 — Allowed discount percentages: 5, 10, 20 only
**Decision:** Service enforces that only 5%, 10%, or 20% discount codes exist; stored as integer in `DiscountCode.percentage`.
**Reason:** Stated requirement. Enforcement is at the data-seeding layer (no management API in v1), not at the HTTP layer.
**Status:** Accepted per requirement.

---

### DL-4 — No discount code management API in v1
**Decision:** Codes are seeded via scripts/fixtures only; no CRUD endpoints.
**Reason:** Not requested in scope; YAGNI. Adds implementation complexity and auth concerns (no real auth in this service) with no immediate need.
**Status:** Accepted. Recorded as Non-Goal §5.

---

### DL-5 — Rounding: floor to nearest cent
**Decision:** `discounted_total = floor(original_total × (100 − pct) / 100)`.
**Reason:** Floors favor the merchant (rounds down the discount, i.e. the buyer pays slightly more), which is the conventional e-commerce choice. Avoids half-cent ambiguity.
**Status:** [ASSUMPTION] — confirm with product owner if rounding direction matters for this use case.
