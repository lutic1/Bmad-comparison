# Implementation Plan: API Rate Limiting

**Branch**: `001-api-rate-limiting` | **Date**: 2026-05-18 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `specs/001-api-rate-limiting/spec.md`

## Summary

Add per-user fixed-window rate limiting to all API endpoints. Each authenticated client (identified by `X-User-Id`) is allowed 100 requests per 60-second window. Excess requests receive HTTP 429. Every response carries `X-RateLimit-*` headers. Implemented with stdlib only — no new dependencies.

## Technical Context

**Language/Version**: Python 3.11+

**Primary Dependencies**: FastAPI 0.115, SQLAlchemy 2.0 (existing — no new deps added)

**Storage**: In-memory `dict` on a module-level singleton; no DB changes

**Testing**: pytest 8.3 (existing)

**Target Platform**: Linux server (single-instance ASGI)

**Project Type**: Web service

**Performance Goals**: Rate limit check adds negligible overhead — one dict lookup and one dict write per request

**Constraints**: No new third-party dependencies (constitution principle V); no changes to individual route files (constitution principle VII)

**Scale/Scope**: Single server instance; in-memory state acceptable per spec assumptions

## Design Notes

### `src/api/rate_limit.py`

```
RateLimiter(limit=100, window_seconds=60)
  ._counts: dict[int, tuple[int, float]]  # user_id → (count, window_start)
  .check(user_id: int, response: Response) → None
      Increments counter; sets X-RateLimit-* headers on response.
      Raises HTTPException(429) if over limit.

get_rate_limiter() → RateLimiter          # module-level singleton factory
check_rate_limit(                         # FastAPI dependency
    response: Response,
    x_user_id: int | None = Header(default=None),
    limiter: RateLimiter = Depends(get_rate_limiter),
) → None
    If x_user_id is None: return (auth dependency handles rejection).
    Else: limiter.check(x_user_id, response).
```

### `src/api/main.py` change

```python
from api.rate_limit import check_rate_limit

app.include_router(users.router, dependencies=[Depends(check_rate_limit)])
app.include_router(orders.router, dependencies=[Depends(check_rate_limit)])
```

`/health` remains on `app` directly — unaffected.

### `tests/conftest.py` change

Add `get_rate_limiter` override to the `client` fixture so each test starts with a fresh `RateLimiter(limit=100)`. Add a separate `rate_limited_client` fixture with `RateLimiter(limit=3)` for tests that need to exhaust the limit quickly.

### Test coverage targets (`tests/test_rate_limit.py`)

1. Request within quota → 200, correct `X-RateLimit-*` headers present
2. `X-RateLimit-Remaining` decrements on each request
3. Request exceeding quota → 429, `Retry-After` header present, `X-RateLimit-Remaining: 0`
4. 429 response body contains `{"detail": "rate limit exceeded"}`
5. Two different users have independent counters (one exhausted does not affect the other)
6. Unauthenticated request (no `X-User-Id`) → 401, no rate limit headers
7. Window reset: counter resets after window expires (test by manipulating `window_start` in the limiter directly)
